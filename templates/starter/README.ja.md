# goodnight-web スターター

お知らせ、ブログ、お問い合わせフォームのある会社のウェブサイトです。
Cloudflare だけで動きます。1つの Worker がページ、お問い合わせフォームの
API、問い合わせを読むための管理画面を配信し、1つの D1 データベースが
問い合わせを保存します。

[English](README.md)

- ページ: トップ、会社概要、サービス、お知らせ、ブログ、お問い合わせ、
  プライバシーポリシー、404。日本語と英語があります。
- コンテンツ: `src/content/` の Markdown ファイル。
- 設定: 会社情報、メニュー、色は `site.config.ts`。
- お問い合わせフォームの項目: コードではなく管理画面（`/admin` の
  **お問い合わせフォーム** ページ）で編集します。
  [お問い合わせフォーム](#お問い合わせフォーム)を参照。
- お問い合わせフォームの API と管理画面は `@goodnight-web/server`
  パッケージに入っています。このパッケージは編集しません。更新は
  プルリクエストで届きます。

サーバー、言語のランタイム、データベースサーバーの保守はありません。
残る作業は、更新のプルリクエストを確認してマージすることです
（[更新](#更新)を参照）。

## デプロイ

> **下書き（DRAFT）。** この手順はまだ最初から最後まで試していません。

1. **Deploy to Cloudflare** ボタンを押します。
   <!-- ボタンはスターターのリポジトリを公開したときに追加します。 -->
2. 設定画面で **Create private Git repository** にチェックを入れます。
   チェックを入れないと、作られるリポジトリは公開（public）になります。
3. 下の表のシークレットを入力します。Cloudflare が Worker と D1
   データベースを作り、サイトをデプロイします。
4. それでもリポジトリが公開で作られた場合は、GitHub で非公開にします:
   **Settings > General > Danger Zone > Change visibility > Private**。
   公開の間は **Visibility check** ワークフローが失敗します。

`npm create cloudflare` を使う場合、プロジェクトは手元のコンピューターに
作られるだけです。GitHub のリポジトリは自分で作り、**Private** を選んで
ください。

## シークレット

Cloudflare のダッシュボード（またはデプロイ時の設定画面）で、Worker の
シークレットとして設定します。このリポジトリのファイルには書かないで
ください。`.dev.vars.example` に説明付きの一覧があります。

| 名前                 | 必須   | 用途                                                                                                 |
| -------------------- | ------ | ---------------------------------------------------------------------------------------------------- |
| `SETUP_TOKEN`        | はい   | ランダムな文字列（32文字以上）。最初の管理者を作るときに `/admin` で一度だけ入力します。             |
| `ADMIN_EMAILS`       | はい   | 管理者になれるメールアドレス。複数ある場合はカンマで区切ります。                                     |
| `BETTER_AUTH_SECRET` | はい   | 管理画面のログイン情報の署名に使う、長いランダムな文字列（32文字以上）。                             |
| `IP_HASH_SECRET`     | はい   | IP アドレスをハッシュ化するためのランダムな文字列（32文字以上）。IP アドレスそのものは保存しません。 |
| `TURNSTILE_SECRET`   | はい   | Turnstile のシークレットキー。未設定の間、お問い合わせフォームは受け付けを停止します。               |
| `SLACK_WEBHOOK_URL`  | いいえ | 新着の問い合わせを知らせる Slack の Incoming Webhook。名前やフォームの入力内容は送りません。         |

## お問い合わせフォーム

お問い合わせフォームの項目（お名前、会社名、種類、内容、追加した項目）は、
管理画面で編集します。`/admin` を開き、**お問い合わせフォーム** ページを
使います。保存するたびに新しい版ができ、デプロイしなくても 1 分ほどで
サイトに反映されます。お問い合わせページは、開いたときに Worker
（`GET /api/contact/form`）から項目を読み込みます。

次の部分は固定で、削除できません: メールアドレスの欄、プライバシー
ポリシーへの同意、迷惑な送信を見分けるための隠し欄（ハニーポット）、
Turnstile の確認。項目を変えたら、プライバシーポリシー
（`src/content/pages/`）の「取得する情報」も書き換えてください。

## Turnstile

お問い合わせフォームは、迷惑な送信を防ぐために Cloudflare Turnstile を
使います。Turnstile を設定するまで、お問い合わせページには「準備中」と
表示され、API も送信を受け付けません。

1. Cloudflare のダッシュボードで、サイトのドメイン用の Turnstile
   ウィジェットを作ります。
2. **サイトキー**を `wrangler.jsonc` の `vars.TURNSTILE_SITE_KEY` に書いて
   コミットします。サイトキーは公開してよい値です。お問い合わせフォームは
   Worker からこの値を読むので、設定する場所はここだけです。ダッシュボード
   だけで設定した値は、次のデプロイで `wrangler.jsonc` の値に置き換わります。
3. **シークレットキー**を Worker のシークレット `TURNSTILE_SECRET` に
   設定します。

詳しい手順はドキュメントの「セットアップ > Turnstile」にあります。

## 最初の管理者

1. `https://<サイトのドメイン>/admin` を開きます。
2. `SETUP_TOKEN` と、`ADMIN_EMAILS` にあるメールアドレスを入力します。
3. パスキーを登録します（スマートフォンや、コンピューターの指紋・顔での
   ログインなど）。パスワードはありません。

最初の管理者を作ると、セットアップの画面は使えなくなります。

## サイトを編集する

- 会社情報、メニュー、色: `site.config.ts`。
  [サイトの色を変える](#サイトの色を変える)を参照してください。
- フォント: `src/styles/global.css`。[フォント](#フォント)を参照してください。
- ページ: `src/pages/`
- お知らせとブログ: `src/content/news/` と `src/content/blog/`
- プライバシーポリシー: `src/content/pages/`。これはひな形で、法的な助言
  ではありません。公開する前に専門家に確認してもらってください。

日本語と英語の内容はそろえてください。AI ツールで編集する場合、ツールは
[AGENTS.md](AGENTS.md) のルールを読みます。

### サイトの色を変える

サンプルのサイトは緑のテーマです。自分の色にするには、`site.config.ts` の
`theme` にある 3 つの値を変えます。

| キー         | 使われる場所                                 |
| ------------ | -------------------------------------------- |
| `primary`    | ボタン、リンク、強調、キーボード操作時の枠線 |
| `background` | ページの背景                                 |
| `foreground` | 本文の文字                                   |

明るい色や濃い色（バッジの背景の薄い色や、リンクの濃い色など）は、
`src/styles/global.css` でこの 3 色から混ぜて作ります。このファイルには、
3 色に連動しない色も書いてあります。エラー（`--color-danger`）、
送信完了（`--color-success`）、トップページの飾りの形
（`--color-decor-wood`、`--color-decor-leaf`）です。

文字が読みやすい色にしてください。`primary` の上の白い文字と、
`background` の上の `foreground` の文字は、コントラスト比 4.5:1 以上が
必要です（WCAG AA）。コントラストのチェックツールで確認してください。

これらの色はサイトにだけ使われます。管理画面（`/admin`）は
`@goodnight-web/server` に含まれていて、独自のテーマのままです。

### フォント

サイトは Web フォントを読み込みません。訪問者の端末に入っているフォントを
使います。フォントの指定は `src/styles/global.css` の `--font-sans`
（すべての文字）と `--font-mono`（コード）の 2 つです。ここを変えると
全ページのフォントが変わります。Web フォントの配信サービスを使う場合は、
プライバシーポリシーにも書いてください。

push する前に、変更を確認します。

```sh
npm install
npm run check
npm run build
npm run dev
```

`npm run dev` で確認できるのはページだけです。お問い合わせフォームと
管理画面を手元で試すには、`.dev.vars.example` を `.dev.vars` にコピーして
値を入れ、`npm run preview` を実行します。サイトをビルドし、手元の
データベースにテーブルを作り、`wrangler dev` で Worker を起動します。

Cloudflare の Turnstile テスト用キー（サイトキー
`1x00000000000000000000AA`、シークレットキー
`1x0000000000000000000000000000000AA`）を使うと手元でもウィジェットは
表示されますが、送信はサーバーに拒否されます。テスト用キーでは Turnstile
がホスト名を `example.com` と返し、action を返さないためです。サーバーは
この2つを確認します。`npm run test:e2e` で実行するエンドツーエンドの
テストは、`e2e/worker.ts` を使ってテスト用キーでもこの確認を通します。
最初に一度 `npx playwright install chromium` が必要です。

## 更新

Dependabot が、パッケージを更新するプルリクエストを作ります
（`.github/dependabot.yml`）。goodnight-web の更新（`@goodnight-web/*`）は、
公開から5日待ってから、1つのプルリクエストにまとめて届きます。
セキュリティの更新は待ちません。

**Update check** ワークフローが、すべてのプルリクエストにコメントします。

- 「goodnight-web の公式アップデートです」: このリポジトリで Dependabot が
  作り、変更が `package.json` と lockfile だけで、`package.json` では
  `@goodnight-web/*` のバージョンだけを変えるプルリクエストです。lockfile
  では `@goodnight-web/*` が使うパッケージも変わることがあります。
  プレビューを確認してからマージしてください。
- 「公式のアップデートではありません」: それ以外のすべてです。変更内容が
  わからない場合は、マージしないでください。

**マージするのは、公式アップデートのコメントがあるプルリクエストだけに
してください。** ほかのパッケージ（Astro など）の更新も Dependabot から
届きますが、警告のコメントが付きます。内容を確認できる人に相談して
ください。

## リポジトリは非公開にする

このリポジトリには、サイトの設定や下書きが入っています。非公開
（private）のままにしてください。公開になっていると **Visibility check**
ワークフローが失敗します。
