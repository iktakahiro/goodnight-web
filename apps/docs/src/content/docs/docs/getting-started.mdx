These steps create a private copy of the starter, enter the secrets, add your own domain, set up Turnstile, and create the first admin.

## What you need

- A Cloudflare account. The free plan is enough for a small website.
- A GitHub account.
- A domain name, if you want the site on your own domain. Decide this before you register a passkey (see [Add your domain](#custom-domain)).

<Steps>

<Step>

### Press the Deploy to Cloudflare button

The button is in the README of the starter repository, the base of your site. It opens a Cloudflare setup form, which asks you to connect GitHub. When you fill in the form and continue, Cloudflare does the rest ([Cloudflare: Deploy buttons](https://developers.cloudflare.com/workers/platform/deploy-buttons/)):

- copies the starter into a new repository in your account
- creates the D1 database
- builds and deploys the Worker with Workers Builds

In the setup form, **tick "Create private Git repository"**. Your repository must be private; [Distribution and updates](/docs/distribution/#private-repository) explains why.

If the repository was created as public, open **Settings > General > Danger Zone > Change visibility** in GitHub and choose private. Until you do, the starter's visibility check workflow fails on every push.

</Step>

<Step>

### Enter the secrets

The same setup form asks for these values. You can also set them later in the Cloudflare dashboard, in the Worker's settings under variables and secrets.

| Name                 | What to enter                                                                                                 |
| -------------------- | ------------------------------------------------------------------------------------------------------------- |
| `SETUP_TOKEN`        | A random string of 32 characters or more. You need it once, to create the first admin. Delete it after setup. |
| `ADMIN_EMAILS`       | The email addresses that may become admins, separated by commas.                                              |
| `BETTER_AUTH_SECRET` | A random string of 32 characters or more. Better Auth uses it to sign sessions.                               |
| `IP_HASH_SECRET`     | A random string of 32 characters or more. Used to hash IP addresses so that raw IPs are never stored.         |
| `TURNSTILE_SECRET`   | The Turnstile secret key. You can leave it empty now and add it in a later step.                              |
| `SLACK_WEBHOOK_URL`  | Optional. A Slack incoming webhook URL for new-inquiry notifications.                                         |

A value shorter than 32 characters counts as missing, and the features that use it stay off.

To make a random string that meets this rule (44 characters), run this in a terminal on your computer:

```sh
openssl rand -base64 32
```

Do not reuse one value for two secrets. Do not commit secrets to the repository.

</Step>

<Step>

### Check the first deploy

Open the site at the address that Workers Builds shows, and check that the pages load.

The database tables exist too, because the `deploy` script applies the D1 migrations before each deploy.

</Step>

<Step>

### Add your domain before you register a passkey [#custom-domain]

A passkey works only on the domain it was registered on (its WebAuthn relying party ID). A passkey registered on a `workers.dev` address stops working when you move the admin screen to your own domain.

Setup is closed by then, so you cannot register a new passkey on the new domain either. There is no recovery procedure for this yet. So add the domain first.

1. In the Cloudflare dashboard, add a custom domain to the Worker.
2. Turn off the `workers.dev` address and preview URLs. The admin screen is then reachable only on your domain.

</Step>

<Step>

### Set up Turnstile

Create a Turnstile widget. For its hostname, use the domain that serves your site. Put its site key in `wrangler.jsonc` (`TURNSTILE_SITE_KEY`) and its secret key in the `TURNSTILE_SECRET` secret.

Until you do, the contact form shows "The contact form is not available yet" and refuses submissions. Follow [Set up Turnstile](/docs/setup/turnstile/).

</Step>

<Step>

### Create the first admin

The admin screen works only over `https://`.

1. Open `https://<your domain>/admin/`. No admin exists yet, so the setup screen (`/admin/setup`) opens.
2. Enter the value of `SETUP_TOKEN` as the **Setup token** and an address from `ADMIN_EMAILS` as the **Email address**, then select **Continue**.
3. Select **Register a passkey** and create the passkey with your browser or password manager. Save it where it syncs across your devices, such as iCloud Keychain, Google Password Manager, or a password manager app. The admin screen has no page to add a second passkey yet ([Passkey sign-in](/docs/how-it-works/passkeys/)).

After the first passkey is registered, setup closes and the setup screen no longer works. Then delete the `SETUP_TOKEN` secret. [First admin setup](/docs/how-it-works/first-admin/) explains the rules.

</Step>

<Step>

### Optional: put Cloudflare Access in front of the admin screen

Cloudflare Access adds a second sign-in, for example a one-time code sent by email. It is free for up to 50 users.

It is recommended but not required. The admin screen always requires a passkey sign-in, with or without Access.

Put the Access application on these paths:

- `/admin`, `/admin/*`
- `/api/admin/*`
- `/api/setup`
- `/api/auth/*`

Keep `/api/contact` public. Visitors send the contact form there.

To have the Worker check the Access token as well, add two variables:

- `ACCESS_AUD`: the application's **Application Audience (AUD) Tag**
- `ACCESS_TEAM_DOMAIN`: for example `your-team.cloudflareaccess.com`

Set both or neither. With only one, the admin paths answer 503. See [Security model](/docs/security/#cloudflare-access).

</Step>

<Step>

### Edit your site

The site has Japanese and English pages. Edit both:

- Company details and the three theme colors: `site.config.ts`
- Pages: `src/pages`
- Posts: `src/content`

The contact form fields are not in the code. Change them in the admin screen ([Customizing the contact form](/docs/contact-form/)).

Have a professional review the privacy policy template before you publish. [Privacy notes](/docs/privacy/) lists what the template covers.

</Step>

</Steps>

## Without the Deploy button

You can also create a project with `npm create cloudflare` (C3). C3 only creates a local project. You create the GitHub repository yourself, so **create it as private**.
