---
title: Slack notifications
description: An optional Slack message about each new inquiry, sent after the response and free of personal data.
---

When you set the Worker secret `SLACK_WEBHOOK_URL` to a Slack incoming webhook URL, goodnight-web sends a short Slack message whenever a new inquiry arrives. The message is sent after the visitor gets a response, and it contains no personal data and no inquiry contents.

## What it does

- **Only Slack is called.** After the Worker saves an inquiry that is not suspected spam, it posts to the webhook. Only an `https://hooks.slack.com/...` address is called; any other URL is ignored.
- **The message has three parts.** The count ("1 new inquiry"), the time the inquiry was received, and a link to the admin screen. It contains no email address, no form field values, and not even the option chosen in a dropdown field. This does not change when admins add fields to the form.
- **The time is shown in each reader's time zone.** The time is sent as a Slack date token, so Slack shows it in each reader's own time zone.
- **Success is recorded; there is no retry.** When the post succeeds, the Worker records `notified_at`. A failed post is not sent again.
- **Suspected spam does not trigger a notification.** That is a submission with a filled honeypot (a field people cannot see) or a spam score of 3 or more. It is saved and listed under **Suspected spam** in the admin screen. See [Contact form protection](/docs/how-it-works/contact-protection/).

## In the code

After the row is saved, the contact API starts the notification only for an inquiry that is not suspected spam:

```ts title="packages/server/src/features/contact/contact-routes.ts"
// 7. After the response: notification (never for suspected spam) and
//    pruning.
const webhookUrl = env.SLACK_WEBHOOK_URL;
if (!suspectedSpam && isSlackWebhookUrl(webhookUrl)) {
  runInBackground(c, 'slack', () =>
    sendSlackNotification({
      db: env.DB,
      webhookUrl,
      submissionId: id,
      payload: buildSlackPayload({
        locale: options.locale,
        receivedAt: now,
        adminUrl: `${origin}/admin/inquiries/${id}`,
      }),
    }),
  );
}
```

The message is built from the received time and the admin URL only:

```ts title="packages/server/src/features/notify/slack.ts"
export const buildSlackPayload = ({
  locale,
  receivedAt,
  adminUrl,
}: {
  locale: Locale;
  receivedAt: number;
  adminUrl: string;
}): SlackPayload => {
  const seconds = Math.floor(receivedAt / 1000);
  const fallback = new Date(receivedAt).toISOString().replace(/\.\d+Z$/, 'Z');
  return {
    text: [
      translate(locale, 'notify.newInquiry'),
      translate(locale, 'notify.receivedAt', {
        time: `<!date^${seconds}^{date_short_pretty} {time}|${fallback}>`,
      }),
      `<${adminUrl}|${translate(locale, 'notify.open')}>`,
    ].join('\n'),
  };
};
```

## Why it is built this way

- **The response does not wait for Slack.** The post runs in `ctx.waitUntil` after the inquiry is saved and the visitor has the response. A Slack outage cannot lose an inquiry or show the visitor an error.
- **No personal data leaves Cloudflare.** Slack is a separate service. Sending only a count, a time, and a link means that inquiry contents stay in your D1 database.
- **No answers are sent at all.** Admins decide what the form asks, so the server cannot know which answers are safe to send.
- **No Cloudflare Queues and no retry.** The admin screen always shows the unread count in its header, so a missed notification does not mean a missed inquiry.
- **The webhook URL is a secret.** Anyone with the URL can post to your channel, so it is kept as a Worker secret and never shown in the admin screen.
