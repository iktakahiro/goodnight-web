## What it does

Right after a deploy, the site has no admin. The setup endpoint `/api/setup` creates the first one, and it accepts a request only if:

- the request comes from the site itself (the `Origin` header is checked),
- the request includes the correct `SETUP_TOKEN` (compared in constant time), and
- the email address is in `ADMIN_EMAILS` (upper and lower case do not matter).

Setup attempts are also rate-limited. The new admin is signed in and then registers a passkey. Once any passkey exists, the setup endpoint closes and stays closed. Until then, setup can run again, so a person who left before registering a passkey is not locked out.

The admin API accepts only a signed-in user who is still in `ADMIN_EMAILS` and has a passkey. The session from setup alone is only good for registering the first passkey.

## Why it is built this way

A newly deployed site is public on the internet before its owner has signed in. If the first visitor to the setup page became the admin, a stranger who found the site first could take it over. Requiring both a secret that only the owner knows and an allowed address closes that gap. Closing setup afterwards means that a leaked `SETUP_TOKEN` cannot create more admins later.

If Cloudflare Access protects the admin paths, only people who pass Access can reach the setup screen at all.
