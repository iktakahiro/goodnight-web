## What it does

- The admin screen and the admin API use [Better Auth](https://better-auth.com/) with its passkey plugin. Better Auth stores its users, sessions, and passkeys in the same D1 database.
- Email and password sign-in is turned off. There is no development bypass, default account, or shared key.
- The Better Auth instance is created for each request from that request's bindings, because Worker bindings are only available per request.
- Cloudflare Access can be added in front of the admin paths. Passkey sign-in is still required with Access.

## Why passkeys

- **No password to steal or reuse.** A passkey is bound to your domain, so a phishing site on another domain cannot use it.
- **CPU limits on the free plan.** A Worker on the free plan gets about 10 ms of CPU time per request. Password hashing (scrypt) is designed to be slow, and Better Auth's password hashing has been reported to exceed that limit on Workers ([better-auth#8860](https://github.com/better-auth/better-auth/issues/8860)). Passkey sign-in checks a signature, which is fast.
- **Nothing extra to run.** Passkeys need no email service and no SMS provider.

## What to know

- **A passkey belongs to one domain.** Register passkeys after you add your own domain. A passkey registered on a `workers.dev` address does not work on your domain.
- **Losing every passkey locks you out.** Register more than one passkey (for example a phone and a laptop) or add a second admin. The recovery procedure is still an open question.
