## What it does

- The admin screen and the admin API use [Better Auth](https://better-auth.com/) with its passkey plugin. Better Auth stores its users, sessions, and passkeys in the same D1 database.
- Email and password sign-in is turned off. There is no development bypass, default account, or shared key.
- The Better Auth instance is built from the Worker's bindings when a request needs it, and reused for later requests in the same isolate. Building it costs about 5 ms of CPU, so building it on every request would use half of the free plan's limit. A new set of bindings gets a new instance.
- Better Auth does not record IP addresses in sessions, and passkey registration and sign-in require user verification (a PIN or biometrics).
- Sign-in requests are rate-limited per hashed IP address with the same Rate Limiting binding as the contact form. Without that binding or `IP_HASH_SECRET`, sign-in is turned off.
- Sign-in, setup, the admin screen, and the admin API work only over `https://` (plain HTTP is allowed on `localhost` for `wrangler dev`). A `GET` over `http://` is redirected to `https://`; other requests get 403.
- Cloudflare Access can be added in front of `/admin/*`, `/api/admin/*`, `/api/setup`, and `/api/auth/*`. With `ACCESS_AUD` and `ACCESS_TEAM_DOMAIN` set, the Worker also checks the Access token. Passkey sign-in is still required with Access. See [Security model](/docs/security/#cloudflare-access).
- The admin API accepts only a session created at or after your first passkey: a passkey sign-in, or the registration of the first passkey. See [First admin setup](/docs/how-it-works/first-admin/#sessions).

## Why passkeys

- **No password to steal or reuse.** A passkey is bound to your domain, so a phishing site on another domain cannot use it.
- **CPU limits on the free plan.** A Worker on the free plan gets about 10 ms of CPU time per request. Password hashing (scrypt) is designed to be slow, and Better Auth's password hashing has been reported to exceed that limit on Workers ([better-auth#8860](https://github.com/better-auth/better-auth/issues/8860)). Passkey sign-in checks a signature, which is fast.
- **Nothing extra to run.** Passkeys need no email service and no SMS provider.

## What to know

- **A passkey belongs to one domain.** Register passkeys after you add your own domain. A passkey registered on a `workers.dev` address does not work on your domain.
- **Losing every passkey locks you out.** Register more than one passkey (for example a phone and a laptop). A second admin cannot be added after setup has closed: a user without a passkey cannot register one then. The recovery procedure is still an open question.
