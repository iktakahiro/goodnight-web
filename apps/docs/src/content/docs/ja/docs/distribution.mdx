## 編集する人で 2 つに分ける

|            | `@goodnight-web/server`（npm パッケージ）                                                                                                                      | あなたのサイト（starter）                                                                                                       |
| ---------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| 編集する人 | goodnight-web の開発者。あなたは編集しません。                                                                                                                 | あなた、またはあなたが使う AI ツール                                                                                            |
| 中身       | Worker の factory、問い合わせ API、Better Auth とパスキー、管理 API、日本語と英語の文言を含むビルド済みの管理画面、セキュリティヘッダー、D1 のマイグレーション | Astro のページ、Markdown のコンテンツ（日本語と英語）、`site.config.ts`、スタイル、`wrangler.jsonc`、3 行ほどの `src/worker.ts` |
| 変わり方   | semver に従った新しいバージョン                                                                                                                                | あなた自身のコミット                                                                                                            |

starter の `src/worker.ts` は factory を呼ぶだけなので、サーバーのコードはパッケージの中にとどまります。starter には `AGENTS.md` と `CLAUDE.md` もあり、AI ツールに編集してよいファイル（`src/pages`、`src/content`、`site.config.ts`、`src/styles`）と、触らないもの（factory の呼び出し、binding の名前、`@goodnight-web/*`）を伝えます。

### 色

サイトと管理画面の色は別々です。サイトの色は starter にあります。主な 3 色は `site.config.ts` の `theme`、そこから混ぜて作る色は `src/styles/global.css` です。サンプルのサイトは緑です。管理画面（`/admin`）はパッケージの中に独自の固定テーマを持っていて、紺色に近い青紫で、ライトとダークのモードがあります。サイトの色を変えても管理画面は変わらず、パッケージを更新してもサイトの色は変わりません。

## コピーの作り方

Deploy to Cloudflare ボタンは、公開されている starter リポジトリを、**あなたの GitHub アカウントの新しいリポジトリ**にコピーします。fork ではなくコピーです。あなたのコピーは starter リポジトリの変更を追いかけません。サーバーのコードは、代わりに npm パッケージを通して届きます。[はじめかた](/ja/docs/getting-started/)を参照してください。

## 更新の届き方

1. goodnight-web が `@goodnight-web/server` の新しいバージョンを公開します。脆弱性の修正なら、GitHub の Security Advisory も出します。
2. starter には `.github/dependabot.yml` が入っています。`@goodnight-web/*` の更新を 1 つにまとめ、数日の cooldown を設定しています。Dependabot は、公開からその日数がたったバージョンだけを提案します。セキュリティアップデートは cooldown で遅れません。
3. Dependabot があなたのリポジトリに PR を 1 つ作ります。
4. Workers Builds がその PR をビルドし、プレビューを表示します。
5. プレビューを確認してマージします。deploy スクリプトは `wrangler d1 migrations apply DB --remote && wrangler deploy` を実行するので、新しいコードが動く前にデータベースのマイグレーションが済みます。

管理画面からのワンクリック更新はありません。あなたの GitHub リポジトリに書き込める token を Worker に持たせる必要があり、goodnight-web は Worker にその権限を持たせない方針です。

### 更新チェックのワークフロー

「update」と書かれた PR が、goodnight-web からの更新とは限りません。starter には `.github/workflows/update-check.yml` が入っていて、すべての PR にコメントを付けて見分けられるようにします。

次のすべてを満たす PR だけを**公式のアップデート**とみなします。

- 作成者が `dependabot[bot]` で、アカウントの種類が `Bot` である。
- ブランチが fork ではなく、あなた自身のリポジトリにある。
- 変更されたファイルが `package.json` と lockfile（`bun.lock`、`package-lock.json`、`pnpm-lock.yaml`）だけである。
- `package.json` で変更された行が、すべて `@goodnight-web/*` の依存関係のバージョンである。

lockfile はほかの部分が変わってもかまいません。新しい `@goodnight-web/server` は、それが使うパッケージ（たとえば `hono`）の新しいバージョンを連れてくることがあり、その変更は lockfile にだけ現れます。サイトが直接使うパッケージは `package.json` に書かれていて、その差分は1行ずつ確認します。すべての変更を確認できない場合、その PR は公式とみなしません。たとえば、GitHub が `package.json` の差分を省略したり途中で切ったりした場合や、変更ファイルの一覧が欠けているおそれがある場合です。

公式のアップデートには「goodnight-web の公式アップデートです。プレビューを確認してからマージしてください。」とコメントします。それ以外には「公式のアップデートではありません。変更内容がわからない場合はマージしないでください。」とコメントします。コメントは日本語と英語で書かれ、新しく増やさずに同じコメントを更新します。

**公式アップデートのコメントが付いた PR だけをマージしてください。**

このワークフローは `pull_request_target` で動くので、コメントを書く権限を持っています。ただし、PR のコードをチェックアウトすることも、実行することもありません。GitHub API で、PR のメタデータと変更されたファイルの一覧だけを読みます。

## リポジトリは private にする [#private-repository]

サイトのコピーは **private** リポジトリに置いてください。public リポジトリでは、サイトのソース全体、設定、すべての変更の履歴（間違えてコミットしたものも含む）が誰にでも見えます。また、知らない人が PR を作れるようになります。これは、更新チェックのワークフローが警告する状況そのものです。

starter には `.github/workflows/visibility-check.yml` が入っています。push のたびに動き、手動でも実行できます。リポジトリが public なら、日本語と英語で「private にしてください」というエラーを出してジョブを失敗させます。token も権限も必要ありません。

GitHub のリポジトリを private にするには、**Settings > General > Danger Zone > Change visibility** を開き、private を選びます。
