## 何をするか

デプロイした直後のサイトには、管理者がいません。セットアップ用のエンドポイント `/api/setup` が最初の管理者を作ります。受け付けるのは、次の両方を満たすリクエストだけです。

- サイト自身から送られている（`Origin` ヘッダーを確認します）。
- 正しい `SETUP_TOKEN` が含まれている（比較にかかる時間が一定になる方法で比べます）。
- メールアドレスが `ADMIN_EMAILS` に入っている（大文字と小文字は区別しません）。

セットアップの試行回数にも制限があります。この制限をかけられないとき（Rate Limiting binding か `IP_HASH_SECRET` がないとき）は、セットアップは使えません。新しい管理者はログインした状態になり、続けてパスキーを登録します。最初のパスキーが登録されると、セットアップのエンドポイントは閉じ、後でパスキーをすべて削除しても閉じた状態が続きます。それまではセットアップをやり直せるので、パスキーを登録する前に離れても締め出されません。

管理 API が受け付けるのは、ログインしていて、まだ `ADMIN_EMAILS` に入っていて、パスキーを持っているユーザーだけです。セットアップで得たセッションだけでは、最初のパスキーの登録しかできません。

## セットアップ画面

管理者がいないサイトで `/admin/` を開くと、`/admin/setup` のセットアップ画面が出ます。手順は 3 つです。

1. **セットアップトークン。** `SETUP_TOKEN`、`ADMIN_EMAILS` に入っているメールアドレス、任意で名前を入力します。トークンの間違い、許可されていないアドレス、セットアップが閉じていることは、それぞれ別のメッセージで知らせます。
2. **パスキー。** **パスキーを登録** を選びます。ブラウザ、スマートフォン、またはパスワード管理アプリがパスキーを作り、指紋・顔・PIN で確認します。画面には、パスキーが結びつくドメインを表示します。
3. **完了。** セットアップが閉じ、管理画面が開きます。次回からは `/admin/login` でパスキーを使ってログインします。

手順 1 のあとで画面を離れても、`/admin/setup` をもう一度開けば手順 2 から続けられます。

## なぜこう作るか

デプロイしたばかりのサイトは、持ち主がログインする前からインターネットに公開されています。セットアップ画面に最初に来た人が管理者になれるなら、先にサイトを見つけた知らない人に乗っ取られるおそれがあります。持ち主だけが知っているシークレットと、許可したメールアドレスの両方を求めることで、このすき間をふさぎます。作成後にセットアップを閉じるので、`SETUP_TOKEN` が漏れても、後から管理者を増やされることはありません。

Cloudflare Access で管理画面のパスを守っていれば、Access を通った人しかセットアップ画面にたどり着けません。
