---
title: Cron を使わない古いデータの削除
description: 保持期間（既定は 180 日）を過ぎた問い合わせは、ふだんのリクエストの中で、多くても 1 時間に 1 回削除します。定期実行のジョブは使いません。
---

## 何をするか

- 問い合わせは保持期間（既定は 180 日）だけ残します。
- 新しい問い合わせを保存した後、Worker は `ctx.waitUntil` の中で `settings.last_cleanup_at` を確認します。前回の削除から 1 時間以上たっていれば、保持期間を過ぎた問い合わせを削除し、`last_cleanup_at` を更新します。
- 管理画面で問い合わせの一覧を開いたときも、同じ削除を行います。新しい問い合わせが来なくても、古いものは消えます。
- `created_at` のインデックスがあるので、削除は速く済みます。
- 同じ削除で、Better Auth の `verification` テーブルにある期限切れの行も消します。パスキーでログインしようとするたびに、ここへチャレンジを書き込みます。使ったチャレンジはすぐ消えますが、途中でやめたものは残り続けてしまいます。チャレンジは数分で期限が切れ、ログインには回数制限があるので、インデックスがなくてもテーブルは小さいままです。
- 管理者は問い合わせを手動で削除したり、CSV で書き出したりもできます。書き出しは 1 回のクエリで 200 行ずつ読んで順に送り出すので、表が大きくても同じように動きます。

## コードでは

問い合わせ API は、応答を用意したあとで削除を始めます。`runInBackground()` は処理を `ctx.waitUntil` に渡し、失敗してもログに書くだけで応答は変えません。

```ts title="packages/server/src/features/contact/contact-routes.ts"
runInBackground(c, 'prune', () => pruneIfDue(env.DB, now));
return c.json({ ok: true });
```

`pruneIfDue()` は、まず `last_cleanup_at` の条件付きの upsert 1 回で実行を確保します。保存されている時刻が 1 時間以上前のときだけ更新するので、2 つのリクエストが同時に来ても、削除するのは片方だけです。保持期間は `settings.retention_days` から読みます（1〜3,650 日。ないときや不正な値のときは 180 日）。

```ts title="packages/server/src/features/retention/prune.ts"
const orm = getDatabase(db);
const claim = await orm
  .insert(settings)
  .values({ key: 'last_cleanup_at', value: String(now) })
  .onConflictDoUpdate({
    target: settings.key,
    set: { value: sql`excluded.value` },
    setWhere: lte(
      sql`cast(${settings.value} as integer)`,
      now - PRUNE_INTERVAL_MS,
    ),
  });
if (claim.meta.changes === 0) return { ran: false };
const retentionDays = await getRetentionDays(db);
const result = await orm
  .delete(submissions)
  .where(lt(submissions.createdAt, now - retentionDays * DAY_MS));
const verifications = await orm
  .delete(verification)
  .where(lt(verification.expiresAt, new Date(now)));
```

## なぜこう作るか

goodnight-web は Cron Triggers を使いません。設定して理解するものを、Worker 1 つとデータベース 1 つだけにするためです。古いデータは決まった時刻ではなく、いずれ消えればよいので、もともと発生するリクエストの中で行えば十分です。1 時間に 1 回までに間引くので、増える処理はわずかです。

削除は応答の後に行うので、問い合わせの送信を遅くしたり失敗させたりすることはありません。

削除した行も、しばらくは D1 の Time Travel で復元できます。[プライバシーについて](/ja/docs/privacy/)を参照してください。
