## 何をするか

`POST /api/contact` は、次の確認を順に行います。前の確認ほど処理が軽いので、ほとんどの迷惑な送信は早い段階で止まります。

| 確認                                                                                    | 失敗したとき                                           |
| --------------------------------------------------------------------------------------- | ------------------------------------------------------ |
| `Origin` がサイト自身のオリジンで、`Content-Type` が想定どおりで、本文が 16 KB 程度まで | 本文を読む前に拒否                                     |
| 見えない honeypot 欄が空である                                                          | 状態を `held` にして保存し、応答は成功のまま           |
| Turnstile の siteverify で `success`、`hostname`、`action` が一致する                   | 400。何も保存しない                                    |
| `ip_hash` をキーにした Rate Limiting binding（例: 60 秒に 5 回）                        | 429                                                    |
| zod で各項目を検証し、スパムスコアを計算する                                            | 不正な入力は拒否。スコアが高ければ状態を `held` にする |

確認が終わったら送信内容を D1 に INSERT し、その後で初めて 200 を返します。

## なぜこう作るか

- **Turnstile はサーバー側で検証します。** ページの中のウィジェットはトークンを作るだけです。siteverify を呼ばなければ、ボットはウィジェットを飛ばして送信できます。`hostname` と `action` も確認するので、ほかのサイトやほかのフォーム用に作られたトークンは使い回せません。
- **honeypot に引っかかっても成功を装います。** エラーを受け取ったボットは、内容を変えて送り直します。成功を受け取ったボットは次へ移ります。送信内容は `held` で残すので、本物の訪問者が誤って引っかかっても、後から見つけられます。
- **怪しい送信は捨てずに保留します。** 問い合わせを取りこぼす損失は、少しのスパムより大きいので、スパムスコアが高い送信は削除せず `held` にします。保留した送信では通知を送りません。
- **回数制限には Cloudflare の binding を使います。** Rate Limiting binding は Worker のインスタンスをまたいで数え、無料プランでも使えます。Better Auth に組み込まれたメモリ上の制限はインスタンスをまたいで数えないので、ここでは使いません。
- **ページにキーを埋め込みません。** 問い合わせページに API キーを入れても誰でも読めるので、何も守れません。守るのは Turnstile と回数制限です。
- **Turnstile がなければ止めます。** `TURNSTILE_SECRET` がなければ、API は 503 を返します。[Turnstile を設定する](/ja/docs/setup/turnstile/)を参照してください。
