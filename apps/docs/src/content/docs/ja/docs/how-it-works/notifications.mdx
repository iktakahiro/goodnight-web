---
title: Slack 通知
description: 新しい問い合わせを Slack に知らせる任意の通知です。応答の後に送り、個人情報を含みません。
---

Worker のシークレット `SLACK_WEBHOOK_URL` に Slack の Incoming Webhook の URL を設定すると、新しい問い合わせが来たときに Slack に短い通知が届きます。通知は訪問者への応答の後に送り、個人情報も問い合わせの内容も含みません。

## 何をするか

- **送る先は Slack だけです。** Worker は、スパムの疑いがない問い合わせを保存した後、Webhook に投稿します。呼び出すのは `https://hooks.slack.com/...` のアドレスだけで、ほかの URL は無視します。
- **中身は 3 つだけです。** 件数（「新しいお問い合わせが 1 件あります」）、受信日時、管理画面へのリンクです。メールアドレスも、フォームの項目の値も、プルダウンの回答も含めません。管理者がフォームに項目を足しても、これは変わりません。
- **日時は読む人の時刻で出ます。** 受信日時は Slack の日付トークンで送るので、Slack は読む人それぞれのタイムゾーンで表示します。
- **成功を記録し、再送はしません。** 投稿に成功したら、Worker は `notified_at` を記録します。失敗しても送り直しません。
- **スパムの疑いは通知しません。** honeypot が埋まっているか、スパムスコアが 3 以上の送信です。保存はして、管理画面の **スパムの疑い** に表示します。[問い合わせフォームの保護](/ja/docs/how-it-works/contact-protection/)を参照してください。

## コードでは

問い合わせ API は、行を保存したあと、スパムの疑いがない問い合わせのときだけ通知を始めます。

```ts title="packages/server/src/features/contact/contact-routes.ts"
// 7. After the response: notification (never for suspected spam) and
//    pruning.
const webhookUrl = env.SLACK_WEBHOOK_URL;
if (!suspectedSpam && isSlackWebhookUrl(webhookUrl)) {
  runInBackground(c, 'slack', () =>
    sendSlackNotification({
      db: env.DB,
      webhookUrl,
      submissionId: id,
      payload: buildSlackPayload({
        locale: options.locale,
        receivedAt: now,
        adminUrl: `${origin}/admin/inquiries/${id}`,
      }),
    }),
  );
}
```

メッセージは、受信日時と管理画面の URL だけから組み立てます。

```ts title="packages/server/src/features/notify/slack.ts"
export const buildSlackPayload = ({
  locale,
  receivedAt,
  adminUrl,
}: {
  locale: Locale;
  receivedAt: number;
  adminUrl: string;
}): SlackPayload => {
  const seconds = Math.floor(receivedAt / 1000);
  const fallback = new Date(receivedAt).toISOString().replace(/\.\d+Z$/, 'Z');
  return {
    text: [
      translate(locale, 'notify.newInquiry'),
      translate(locale, 'notify.receivedAt', {
        time: `<!date^${seconds}^{date_short_pretty} {time}|${fallback}>`,
      }),
      `<${adminUrl}|${translate(locale, 'notify.open')}>`,
    ].join('\n'),
  };
};
```

## なぜこう作るか

- **応答は Slack を待ちません。** 投稿は、問い合わせを保存して訪問者に応答した後、`ctx.waitUntil` の中で行います。Slack が止まっていても、問い合わせを失うことも、訪問者にエラーを見せることもありません。
- **個人情報を Cloudflare の外に出しません。** Slack は別のサービスです。件数、日時、リンクだけを送るので、問い合わせの内容はあなたの D1 データベースにとどまります。
- **どの回答も送りません。** フォームで何を尋ねるかは管理者が決めるので、どの回答なら送ってよいかをサーバーは判断できません。
- **Queues も再送も使いません。** 管理画面のヘッダーには未読件数が常に出ています。通知を見逃しても、問い合わせを見逃すことにはなりません。
- **Webhook の URL はシークレットです。** URL を知っている人は誰でもチャンネルに投稿できます。そのため Worker のシークレットとして持ち、管理画面にも表示しません。
