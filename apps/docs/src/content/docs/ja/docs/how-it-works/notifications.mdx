---

<Callout type='info'>
  コードの抜粋は、サーバーのパッケージができたら追加します。
</Callout>

## 何をするか

- `SLACK_WEBHOOK_URL` が設定されていれば、Worker は状態が `new` の問い合わせを保存した後、その Slack Incoming Webhook に投稿します。
- 通知に含めるのは、件数（「新しい問い合わせ 1 件」）、種別、管理画面へのリンクだけです。名前、メールアドレス、電話番号、本文は含めません。
- 投稿に成功したら、Worker は `notified_at` を記録します。再送はしません。
- 保留やスパムの送信では通知しません。

## なぜこう作るか

- **応答は Slack を待ちません。** 投稿は、問い合わせを保存して訪問者に応答した後、`ctx.waitUntil` の中で行います。Slack が止まっていても、問い合わせを失ったり、訪問者にエラーを見せたりすることはありません。
- **個人情報を Cloudflare の外に出しません。** Slack は別のサービスです。件数とリンクだけを送るので、問い合わせの内容はあなたの D1 データベースにとどまります。
- **Queues も再送も使いません。** 管理画面のヘッダーには未読件数が常に出ているので、通知を見逃しても問い合わせを見逃すことにはなりません。
- **Webhook の URL はシークレットです。** URL を知っている人は誰でもチャンネルに投稿できるので、Worker のシークレットとして持ち、管理画面にも表示しません。
