## 部品

| 部品                      | 役割                                                                                                                                                                                                                          |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Worker                    | サイトごとに 1 つ。静的なページを配信し、API を動かします。                                                                                                                                                                   |
| Static Assets             | Astro のビルド結果（`/`、`/blog/`、`/contact/` など）。Cloudflare が Worker のコードを動かさずに配信します。                                                                                                                  |
| Hono アプリ               | `@goodnight-web/server` の `createGoodnightWorker(options)` で作ります。`run_worker_first` により、`/api/*`、`/admin`、`/admin/*` だけがここに届きます。                                                                      |
| D1                        | SQLite のデータベース 1 つ。問い合わせ、設定、Better Auth のテーブルを入れます。マイグレーションは npm パッケージに入っています。                                                                                             |
| Turnstile                 | 問い合わせフォームのボット対策（Cloudflare 製）。Worker がトークンをサーバー側で検証します。                                                                                                                                  |
| Rate Limiting binding     | `ip_hash` ごとに、問い合わせの送信、セットアップ、パスキーでのログインの回数を制限する Workers の binding。無料プランで使えます。                                                                                             |
| Better Auth とパスキー    | 管理者のログイン。パスキーだけを使い、メールとパスワードでのログインは無効にします。                                                                                                                                          |
| 管理画面                  | React と TanStack Router、Form、Table で作り、Vite でビルドしたアプリ。ビルド済みで `@goodnight-web/server` に入っていて、Worker が配信します。                                                                               |
| Slack Webhook（任意）     | 「新しい問い合わせ」の短い通知。個人情報は含めません。                                                                                                                                                                        |
| Cloudflare Access（任意） | `/admin`、`/admin/*`、`/api/admin/*`、`/api/setup`、`/api/auth/*` の前に置く、もう 1 段のログイン。推奨ですが必須ではありません。`ACCESS_AUD` と `ACCESS_TEAM_DOMAIN` を設定すると、Worker も Access のトークンを確認します。 |

設計を決めている制約:

- Worker 1 つと D1 データベース 1 つ。Queues、Cron Triggers、KV は使いません。
- 必須の外部サービスは Cloudflare と GitHub だけです。
- 安全側に倒します。設定やシークレットが足りないときは、それを必要とする機能を止めます。

## ルート

| パス                             | 使う人             | 内容                                                                                                                                                                                                                              |
| -------------------------------- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `/`、`/blog/*`、`/contact/` など | 訪問者             | 静的なページ。Worker のコードは動きません。                                                                                                                                                                                       |
| `GET /api/contact/form`          | 問い合わせページ   | 現在のフォームの項目と、フォームが使えるかどうか。公開の読み取り専用です。                                                                                                                                                        |
| `POST /api/contact`              | 問い合わせフォーム | 確認、回数制限をして、送信内容を保存します。                                                                                                                                                                                      |
| `/api/setup`                     | 最初の管理者       | 最初の管理者を作ります。パスキーが登録されたら閉じます。                                                                                                                                                                          |
| `/api/auth/*`                    | 管理者             | Better Auth。パスキーの登録とログイン。                                                                                                                                                                                           |
| `/api/admin/*`                   | 管理画面           | 一覧（50 件ずつ、受信日時の順。未読件数とスパムの疑いの件数、メールアドレスの検索付き）、詳細、未読・既読とスパムの疑いの変更、削除、CSV の書き出し、フォームの編集とそのバージョン、Turnstile が設定済みかを返すステータス API。 |
| `/admin/*`                       | 管理者             | ビルド済みの管理画面（React アプリ）。データの取得には必ずセッションが必要です。                                                                                                                                                  |

## 問い合わせ 1 件の流れ

`POST /api/contact` は次の順に処理します。

1. **Origin とサイズ。** サイト自身のオリジンからのリクエストで、`Content-Type` が想定どおりで、小さい（32 KB まで）ことを確認します。それ以外は本文を読む前に拒否します。
2. **honeypot。** フォームには人には見えない欄（`gnw_hp_x`）があります。Worker は、ここが埋まっているかを記録して先へ進みます。honeypot が埋まっていても応答は変わらず、5 で印を付けるだけです。
3. **Turnstile。** Worker がトークンを Turnstile の siteverify に送り、`success`、`hostname`、`action` を確認します。失敗したら 400 を返し、何も保存しません。
4. **回数制限。** Rate Limiting binding が `ip_hash` ごとにリクエストを数えます。上限を超えたら 429 を返します。
5. **入力の検証とスパムスコア。** zod でメールアドレスと同意を確認します。フォームの項目は、ブラウザーから送られたものではなく、D1 にある現在のフォームの定義から組み立てた zod のスキーマで確認し、知らない項目や、リクエストの本文にある知らないキーは拒否します。訪問者のページが古いバージョンのフォームだった場合は 409 `form_outdated` を返します。簡単なルールでスパムスコアを加点します。スコアが 3 以上か honeypot が埋まっていれば、スパムの疑いの印を付けます。その場合も、状態 `unread`（未読）で保存します。
6. **保存してから応答。** D1 に行を INSERT します。INSERT が成功してから、訪問者に 200 を返します。この後の処理が応答を変えることはありません。
7. **応答の後、`ctx.waitUntil` の中で:**
   - スパムの疑いがなく、Slack Webhook が設定されていれば、「新しい問い合わせ 1 件・受信日時・管理画面の URL」を送り、`notified_at` を記録します。
   - 前回の削除から 1 時間以上たっていれば、保持期間（既定は 180 日）を過ぎた問い合わせと、期限切れのパスキーのチャレンジを削除します。

問い合わせ API はフェイルクローズです。`TURNSTILE_SECRET` か `TURNSTILE_SITE_KEY` が設定されていない、`IP_HASH_SECRET` がないか 32 文字より短い、または Rate Limiting binding がない場合、この API は 503 を返し、フォームには「まだ利用できません」と表示します。[Turnstile を設定する](/ja/docs/setup/turnstile/)を参照してください。

## コードでは

サイトの Worker は 3 行です。サイトの既定の言語を、`@goodnight-web/server` のファクトリーに渡します。

```ts title="templates/starter/src/worker.ts"
import { createGoodnightWorker } from '@goodnight-web/server';
import { siteConfig } from '../site.config';

export default createGoodnightWorker({ locale: siteConfig.defaultLocale });
```

`wrangler.jsonc` は、API と管理画面のパスだけを Worker に送ります。それ以外のパスは、Worker のコードを動かさずに Static Assets が返します。

```jsonc title="templates/starter/wrangler.jsonc"
"assets": {
  "directory": "./dist",
  "binding": "ASSETS",
  "not_found_handling": "404-page",
  // The contact API and the admin screen run in the Worker. Every other
  // path is a page from ./dist.
  "run_worker_first": ["/api/*", "/admin", "/admin/*"],
},
```

ファクトリーは Hono アプリを 1 つ作ります。最初にセキュリティヘッダー、HTTPS、Cloudflare Access のミドルウェアが動き、続いて機能ごとに自分のルートをマウントします。どのルートにも当たらないリクエストは `ASSETS` binding に渡ります。

```ts title="packages/server/src/app.ts"
app.use('*', securityHeaders);
// The admin UI, admin API, setup, and Better Auth: HTTPS only (except on
// localhost), then Cloudflare Access when ACCESS_AUD and
// ACCESS_TEAM_DOMAIN are set.
app.use('*', requireHttps);
app.use('*', requireAccess);
app.route('/api/contact', contactRoutes);
app.route('/api/setup', setupRoutes);
app.route('/api/auth', authRoutes);
app.route('/api/admin', adminRoutes);
app.all('/api/*', (c) => apiError(c, 404, 'not_found'));
app.on(['GET', 'HEAD'], ['/admin', '/admin/*'], (c) =>
  serveAdminFile(c.req.raw),
);
```

機能（問い合わせ、セットアップ、認証、管理 API、管理画面）は、それぞれ `packages/server/src/features/` の下の自分のフォルダーにあります。

## シークレットと binding

| 名前                   | 種類                   | 用途                                                                                                  |
| ---------------------- | ---------------------- | ----------------------------------------------------------------------------------------------------- |
| `DB`                   | D1 binding             | 保存するデータのすべて                                                                                |
| `ASSETS`               | Static Assets binding  | Astro でビルドしたページ                                                                              |
| `CONTACT_RATE_LIMITER` | Rate Limiting binding  | `ip_hash` ごとの、問い合わせ、セットアップ、パスキーでのログインの回数制限                            |
| `TURNSTILE_SITE_KEY`   | 変数                   | 公開してよい Turnstile のサイトキー。`wrangler.jsonc` に書きます。ないと問い合わせ API は止まります。 |
| `SETUP_TOKEN`          | シークレット           | 最初の管理者を作るときに必要。32 文字以上。セットアップ後に削除します。                               |
| `ADMIN_EMAILS`         | シークレットまたは変数 | 管理者になれるメールアドレス                                                                          |
| `BETTER_AUTH_SECRET`   | シークレット           | Better Auth の署名用。32 文字以上。                                                                   |
| `IP_HASH_SECRET`       | シークレット           | `HMAC-SHA256(ip, IP_HASH_SECRET)` の鍵。32 文字以上。                                                 |
| `TURNSTILE_SECRET`     | シークレット           | Turnstile の siteverify。ないと問い合わせ API は止まります。                                          |
| `SLACK_WEBHOOK_URL`    | シークレット（任意）   | 新しい問い合わせの通知                                                                                |
| `ACCESS_AUD`           | 変数（任意）           | Cloudflare Access アプリケーションの AUD タグ。`ACCESS_TEAM_DOMAIN` と一緒に設定します。              |
| `ACCESS_TEAM_DOMAIN`   | 変数（任意）           | Cloudflare Access のチームドメイン。たとえば `your-team.cloudflareaccess.com`。                       |

32 文字より短いシークレットは、ないのと同じ扱いで機能を止めます。シークレットは Worker の中にとどめます。ブラウザに返すことも、D1 に書くこともありません。

`/admin`、`/admin/*`、`/api/admin/*`、`/api/setup`、`/api/auth/*` は `https://` でだけ動きます（`localhost` を除きます）。[セキュリティモデル](/ja/docs/security/#https)を参照してください。

## スタイルとフォント [#styles-and-fonts]

Web フォントはどこでも読み込みません。サイトでも、管理画面でも、このドキュメントサイトでもです。それぞれがシステムフォントの並びを CSS のトークンとして 1 か所で決めているので、文字は訪問者の端末にすでにあるフォント（たとえば macOS と iOS ではヒラギノ、Windows ではメイリオや游ゴシック）で表示されます。フォントのファイルも、フォントの配信サービスも使わず、Content Security Policy にフォント用のホストもありません。

スターターは自分のトークンを持ちます。テーマの 3 色は `site.config.ts`（`theme.primary`、`theme.background`、`theme.foreground`）から取り、CSS 変数として `<html>` に設定します。ほかの色合いはこの 3 色から混ぜて作るので、3 つの値を変えればサイト全体の色が変わります。

```css title="templates/starter/src/styles/global.css"
:root {
  --site-primary: #7357c8;
  --site-background: #fcfbff;
  --site-foreground: #2f2a40;
}

@theme inline {
  --font-sans:
    'Hiragino Sans', 'Hiragino Kaku Gothic ProN', 'Noto Sans JP',
    'BIZ UDPGothic', Meiryo, system-ui, -apple-system, 'Segoe UI', sans-serif;

  --color-background: var(--site-background);
  --color-foreground: var(--site-foreground);
```

管理画面は `@goodnight-web/server` の中に自分のトークンを持っているので、サイトの色を変えても管理画面の色は変わりません。
