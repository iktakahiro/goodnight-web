## What you get

goodnight-web gives you the three things most websites need:

- **Pages and a blog.** A website built with Astro, with a home page, company profile, services, news, blog, contact page, and privacy policy, in Japanese and English. Blog posts are Markdown files in the repository.
- **A contact form.** You add, remove, and reorder its fields in the admin screen, with no code changes and no deploy. Submissions are checked with Turnstile (Cloudflare's bot check) and rate limited. Each one is saved to D1 (Cloudflare's database) before the visitor gets a response.
- **An admin screen for inquiries.** You sign in with a passkey: a fingerprint, face, or device PIN instead of a password. You can read inquiries, mark them unread or read, search by email address, review suspected spam separately, delete inquiries, export them as CSV, and edit the form fields.

## What it runs on

Everything runs on Cloudflare: one Worker with Static Assets, which serves the pages and runs the API, and one D1 database.

The only other service is GitHub, where your website's repository lives. Slack notifications are optional.

## Who it is for

- A developer or a small web agency that builds websites for clients and hands them over.
- Someone at a small company or startup who looks after the website. It also fits people without an engineering background who edit the site with AI tools.

You do not need to write server code. The contact API and the admin screen come from an npm package that you do not edit.

## What you still maintain

There are no servers or runtimes to maintain. Some work remains, so plan for it:

- **Review and merge dependency update pull requests.** Fixes to goodnight-web arrive in your repository as pull requests from Dependabot, GitHub's tool that opens update pull requests. They are not merged automatically; you review and merge them.
- **Update the website's own dependencies**, such as Astro and Tailwind CSS. These also arrive as Dependabot pull requests.
- **Keep up with Cloudflare changes**, such as a new `compatibility_date` (the date that sets which Workers runtime behavior you get) or a change to a free plan limit.
- **Keep your repository private.** Also keep your Worker secrets (private values stored with the Worker) safe.
- **Have a professional review your privacy policy** before you publish it.
